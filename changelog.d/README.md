# Changelog fragments

`CHANGELOG.md` is generated by [towncrier](https://towncrier.readthedocs.io) when a release is drafted: **do not edit it
by hand**. Instead, every pull request adds one small file per change to this directory.

## File name

```text
changelog.d/<pull request or issue number>.<type>.md
changelog.d/+<short-description>.<type>.md         (when there is no number yet)
```

| Type         | Use it for                                                        |
| ------------ | ----------------------------------------------------------------- |
| `added`      | New hooks, options or other features                              |
| `changed`    | Changes in existing behaviour (including dropped Python versions) |
| `deprecated` | Features that will be removed in a future release                 |
| `removed`    | Features that were removed                                        |
| `fixed`      | Bug fixes                                                         |
| `security`   | Fixes for vulnerabilities                                         |
| `repository` | CI, tooling, tests, documentation: anything users will not notice |

## Content

One sentence of Markdown, written like the existing entries of `CHANGELOG.md`: no heading, no leading `- `, and all
on a single line. For example `changelog.d/+lizard-exit-code.fixed.md`:

```markdown
Fix lizard hook only considering the exit code of the last file
```

Use several files if a pull request contains several changes worth mentioning.

## Preview

```bash
python -m pip install towncrier
python -m towncrier build --draft --version 0.0.0
```

Without `--draft`, towncrier rewrites `CHANGELOG.md` and deletes the fragments: leave that to the "Draft new release"
workflow.
